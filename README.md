# FUTEDU Bioimpedance Tracker

Single-file web app (`index.html`) backed by Supabase. **No player data lives in this folder**: the app only holds the (public by design) Supabase URL and anon key. Access is controlled by login + Row Level Security, so without signing in the database returns nothing.

## One-time setup
1. Create the Supabase project `futedu` (EU region).
2. **SQL Editor**: run `schema.sql` (tables + RLS).
3. **Authentication → Users → Add user** (email + password) and **Authentication → Sign In / Providers → disable "Allow new users to sign up"**.
4. **Project Settings → API**: copy the *Project URL* and the *anon public* key into `SUPABASE_URL` / `SUPABASE_ANON_KEY` at the top of the script in `index.html`. Never use the `service_role` key.
5. Load the existing data once with the migration SQL (generated outside the repo, never committed), then open the app and check the roster and September history.

## Publishing (GitHub Pages)
Publish this folder from a **separate public repository that contains only these files** (`index.html`, `schema.sql`, `README.md`). Do not make the main FUTEDU repo public: its Git history still holds player data.

## Features
- **Anthropometry reports and exports**: besides the player report, a one-page **Round report** (everyone assessed in the current round with their results, group means and ranges, change in Σ6 vs the previous assessment, pending and incomplete players) and a **Pending list** to print and tick; list sortable by name, pending first, age or oldest assessment. Settings → Data: **Back up everything (JSON)** (players, bioimpedance, anthropometry, notes, tags, thresholds, check-ins; shows what was saved), plus bioimpedance and anthropometry CSV.
- **Phones**: fixed scale (no pinch/double-tap zoom and no zoom on focus: fields are 16 px), anthropometry list as cards, full-screen New assessment with sticky actions.
- **Anthropometry evolution and round history**: the player page has evolution charts (sum of 6, fat, muscle across assessments). "Start a new round" asks for a name for the round that ends and the new start date; closed rounds stay in a **Previous rounds** table with who was and was not assessed in each (worked out from the assessment dates).
- **Imports pick the round from the date**: each report (photo/PDF) goes into the round that was open on its date (a September report goes into September, not the current round), editable per report; the CSV dialog does the same from the dates in the file. When a full report carries the height (and sex), the review can save them into the shared player data. A single measurement can be edited (values, date, balance, and the round it is filed in, to move a misfiled one) or deleted from the player's page; a reading whose date does not fit its round is flagged "check round", and the player page says when the current round has no measurement for them yet.
- **Round order**: rounds always run oldest to newest (closed rounds by closing date, the open round last), whatever order the database returns them in, so charts, history and "vs previous" comparisons put the current round last.
- **Printing**: reports are laid out off-screen at A4 width, measured and tightened until they fit one page with room to spare (printers and phones add their own margins); rows, pills and notes never split across pages and the footer sits at the bottom of the page. Phone, tablet and desktop spacing was harmonised (dashboard tiles, filters and player actions on phones).
- **Shared player data**: date of birth, sex and height are one record per player (the anthropometry profile). The Bioimpedance player page has a "Player data" card that shows and edits that same record, so it is entered once and seen in both sections; measurements are never mixed between them. With the date of birth, both lists can be filtered by age group (**U18** = under 18, **U23** = 18 to 22, by age today); the filter is shared by the two sections and also scopes the anthropometry counters, round report and pending list.
- **Recipes**: library of the workshop material, grouped by recipe (recipe card, session guide, printable handouts, facilitator keys) plus the general sessions; PDFs open or download, session guides are read in the app; searchable. The files are a generated copy in `library/` (see CLAUDE.md), public like the rest of the site.
- **Dashboard**: KPIs, players needing attention, team average body fat by round, results by group (tags), classification overview, pending list, backup reminder.
- **Bioimpedance**: search, filters (pending / measured / flagged / health notes), group filter, sort, check-ins, per-player cards, **Quick entry** table for typing many players at once.
- **Player profile** (`#player/<id>`, opened by clicking the player's name or avatar in the list or in quick entry): evolution charts (body fat, fat-free mass, hydration), all measurements, dated health notes, tags and a **printable one-page PDF report** (same look as the round report, weight first, footer at the bottom of the A4 page) (browser print dialog; health notes are optional).
- **Round report**: one A4 "Flagged Players Report" (dark header, counters, one table per target: body fat, subcutaneous fat, hydration, BMI, skeletal muscle, plus visceral fat, fat-free mass and asymmetry when there is data). Create it any time from Bioimpedance > *Round report*, from Settings > Rounds (any past round), or right after archiving a round. Optional group filter; lists unmeasured players. Uses the browser print dialog: choose *Save as PDF* (file name suggested: `futedu-nutrition-report-DDMMYYYY`).
- **Rename rounds**: Settings lists every bioimpedance round with a Rename button (the current one can be renamed too; empty shows "Current"); the anthropometry "Previous rounds" table has one as well. Closed rounds always keep a name.
- **Restore a backup**: Settings > Data > "Restore from a JSON backup…" reads a file made by "Back up everything", shows what it holds and adds what is missing (players, rounds, readings, settings); it never deletes, and only overwrites if you untick "Only add what is missing".
- **Anthropometry**: per-player profile with the fixed data (date of birth, sex, ethnicity, height, sitting height, arm span; editable if re-measured, and each assessment keeps its own copy so past results do not change) and assessments with body mass, 6 skinfolds and 4 girths, each taken once or three times (with three readings the mean is used, otherwise the first; a warning above 1 % / 5 % between the first two suggests a third reading). Results: sum of 6 skinfolds, fat (Yuhasz, and Slaughter for young people), adipose tissue (Ross and Kerr), muscle (Lee), residual mass, BMI, corrected girths and muscle areas, cormic index, relative arm span, fat distribution; change vs the previous assessment (labels a change "substantial" when it exceeds the usual variation between measurements) and comparison with the academy group; a one-page A4 report with a neutral written summary (it tightens spacing and shows fewer past assessments if needed so it never spills onto a second page). **Import past assessments** from the Excel anthropometry workbook (.xlsx/.xlsm, first sheet; several files at once or by dropping them on the page): name, sex, ethnicity, date of birth, the assessment and, when filled in, the previous one; a review screen lets you correct everything, match the player and skip or replace existing dates. Read on the device, nothing is uploaded. PDF import is not needed: every past PDF has its Excel, which is the better source. **Rounds**: the current round starts on a date (default: start of the half-year; editable, or "Start a new round" for today); the list shows who is Done or Pending in it, with a filter, a counter and a Measure button, so imported past assessments do not count as the new round. The **New assessment** screen has a live preview (entered measures, sum of 6, fat, muscle, BMI), the previous values next to each field, Enter to jump to the next measure, a sticky footer and "Save and next pending player". Stored in the settings table (`anthro_round`).
- **Dashboard**: a quiet Anthropometry line (players assessed in the current round, pending count, last assessment), since assessments are done once a semester while bioimpedance is monthly.
- **Compare**: any two rounds, any measure, optionally per group, with group average.
- **Import report**: photos/screenshots (JPG, PNG, WebP) and PDFs of Arboleaf reports (summary screen or full "Body Composition Analysis" report). Text is read on the device with OCR (Tesseract.js and PDF.js are loaded from a CDN the first time; files are never uploaded), values are cross-checked, and you review and correct everything before saving. **Two report formats are understood**: the simplified one (under-18, a single screen: weight, body fat, BMI, BMR, fat-free mass, subcutaneous fat, body water, with decimal commas or points) and the full "Body Composition Analysis" A4 report (adults), which is a fixed template: every value is read from its own small area with a digits-only pass, cross-checked (weight = fat-free mass + fat mass; BMI from height), the muscle-balance check boxes are detected, and the review screen shows age, sex and height from the report. Player names with a small spelling difference are still matched. The simplified report has no visceral fat, skeletal muscle or muscle balance (Arboleaf does not include them), so those stay empty.
- **Settings**: thresholds, rounds (archive), **CSV import** and photo/PDF import can save into **any round**, not only the current one, with an option to only fill empty values (to complete a past month without touching what is already saved; CSV accepts the muscle balance columns too), CSV/JSON export.
- **Check-ins** are shared across devices (stored in the `settings` table, key `checkins`) and cleared when a round is archived.
- **Light, dark or automatic theme** (toggle in the side menu; remembered on the device; printed reports are always light), toast notifications, drag-and-drop import anywhere, and a `/` shortcut to search players.
- **App shell**: dark theme by default (light and automatic available), a loading screen on start-up (with a hint and a Reload button if the connection is slow), **refresh by pulling down** on a phone or **scrolling up at the top** on a computer (reloads the data; refuses if Quick entry has unsaved values), a **Recipes** section (placeholder for now) and **Install app** (Windows via Edge/Chrome, Android, desktop; manual steps shown for iPhone).
- Responsive layout with a mobile drawer menu.

## Notes on data storage
No database updates are ever needed after setup: dated health notes, player tags and check-ins are stored in the existing `settings` table (keys `player_notes`, `player_tags` and `checkins`). The first time the app loads, it carries over each player's old single health note automatically. Both are included in the JSON export.

## Tests
`npm ci`, `npx playwright install chromium`, then `npm test`. The tests open `index.html` from disk with a mocked Supabase client and made-up players (no network, no real data) and cover the anthropometry rounds, assessment form, reports (one A4 page), imports into a previous round, shared player data, age filters, backup and the mobile layout. They run automatically on every pull request.
